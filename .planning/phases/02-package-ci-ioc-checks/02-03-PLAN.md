## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| scanned lockfiles -> scanner | attacker-controlled, possibly large JSON/YAML/text |
| iocs.json -> scanner | local, hand-edited; may be missing or malformed |
| scanner -> output | must not leak file content |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-10 | Denial of Service | json.loads on huge/deep package-lock.json | mitigate | read_text 1 MB cap; catch JSONDecodeError/RecursionError/ValueError -> low; v1 recursion over `dependencies` collected inside the try |
| T-02-11 | Denial of Service | missing/malformed iocs.json | mitigate | load_iocs never raises; low H5 finding |
| T-02-12 | Tampering | symlinked iocs.json or lockfile | mitigate | read_text O_NOFOLLOW; lockfiles via existing symlink finding path |
| T-02-13 | Information Disclosure | findings | mitigate | pattern name + line only, no package text |
| T-02-14 | Spoofing | stale iocs.json misses new malware | accept | documented v1 limit (STATE.md concern); H3/H4 pattern checks are primary |
| T-02-15 | Repudiation | placeholder IOCs mistaken for real intel | mitigate | entries named `dev-guard-ioc-placeholder` plus `_comment` key stating they are fake |
</threat_model>
