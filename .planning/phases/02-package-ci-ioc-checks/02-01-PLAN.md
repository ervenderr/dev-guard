## Phase Goal

**As a** solo developer on macOS, **I want to** get findings for malicious install scripts, workflow token theft, unpinned actions and known-bad lockfile entries, **so that** supply-chain worm payloads are caught before or after they run.

<objective>
Vertical slice for H3: a `package.json` with a malicious `preinstall`/`install`/`postinstall` script is detected end-to-end through `scan()`.

Also generalizes scan dispatch from the fixed `TARGETS` dict lookup to a small `target_for(path)` function so plans 02 (workflows: path depends on grandparent dir + suffix) and 03 (lockfiles: `requirements*.txt` glob) can plug in. This is the only structural change in the phase; it is required because H3-H5 targets cannot be expressed as a `(parent, filename)` key.

Output: H3 check in checks.py, constants in patterns.py, fixtures, tests/test_h3.py.
Commits: `<type>: <description>`, no attribution lines. Never stage SPEC.md or .claude/.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Information Disclosure | check_package_json findings | mitigate | Findings carry only pattern name + line; test asserts FAKE_SECRET_TOKEN_H3 absent from every Finding |
| T-02-02 | Denial of Service | json.loads on hostile package.json | mitigate | read_text 1 MB cap; catch JSONDecodeError/RecursionError/ValueError -> low finding |
| T-02-03 | Tampering | symlinked package.json pointing outside tree | mitigate | target_for feeds existing _symlink_findings; O_NOFOLLOW read |
| T-02-04 | Elevation of Privilege | executing scanned scripts | mitigate | text parse only, no subprocess anywhere in checks.py |
