From dev_guard/patterns.py: `H1_PATTERNS: dict[name, Pattern]` built from `_SHELLS` and `_WRAPPERS`, `SEVERITY_*`, `PATTERN_MALFORMED_JSON`, `PATTERN_NOT_IN_ALLOWLIST`, `HOOK_ALLOWLIST`, `MAX_FILE_BYTES`.

Root cause of the ReDoS (current patterns.py): `_WRAPPERS` and the pipe branch of `remote_shell` use `(?:\S*/)?`. On `"|a"*N`, `\S*` runs to end of line from every `|` and backtracks looking for `/`: O(N^2) (~7s at 80 KB). The `.*`-after-keyword branches (`python -c ... .*`, `node -e ... .*`, `sh -c ... .*`) and `base64\b[^|;&]*\s-d` have the same shape: each keyword occurrence rescans to the end.

Python is 3.12 (.venv): atomic groups `(?>...)`, possessive quantifiers `*+`, and scoped flags `(?m:^)` are available.

Tests call `scan(fixture_dir, extra_files=())` and assert on `{(f.pattern, f.line)}`; venv: `.venv/bin/python -m pytest -q`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| scanned package.json -> scanner | attacker-controlled file content parsed as JSON |
| scanned text -> H1 regexes | attacker-controlled lines of up to 1 MB |
| scanner -> terminal/JSON output | findings may later reach n8n; must never include file content |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Information Disclosure | check_package_json findings | mitigate | Findings carry only pattern name + line; test asserts FAKE_SECRET_TOKEN_H3 absent from every Finding |
| T-02-02 | Denial of Service / Spoofing | json.loads on hostile or deeply nested package.json | mitigate | read_text 1 MB cap; JSONDecodeError/ValueError -> low; RecursionError -> low + raw-line fallback on lifecycle lines so nesting cannot hide a malicious postinstall |
| T-02-03 | Tampering | symlinked package.json pointing outside tree | mitigate | target_for feeds existing _symlink_findings; O_NOFOLLOW read |
| T-02-04 | Elevation of Privilege | executing scanned scripts | mitigate | text parse only, no subprocess anywhere in checks.py |
| T-02-05 | Spoofing | obfuscated install script evading regex | accept | documented v1 limit; non-allowlisted scripts still get med |
| T-02-07 | Denial of Service | catastrophic backtracking in shared H1 regexes (remote_shell `\S*/` was O(N^2): ~7s at 80 KB, hang at 1 MB; affects H1-H4) | mitigate | regexes rewritten linear (possessive path prefix, atomic first-keyword-per-line/segment); tests/test_redos.py bounds each pattern on ~1 MB inputs at < 1s; plus MAX_LINE_LEN=4096 cap in H3/H4 emits low oversize_line instead of matching |
