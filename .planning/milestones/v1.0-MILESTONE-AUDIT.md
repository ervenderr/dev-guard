## 3. Tech debt

**Unverified, need a human (outward-facing by design, D-06):**
1. n8n import and execution. The `typeVersion` values (webhook 2, code 2, if 2, telegram 1.2) and the IF v2 condition shape were written from memory. Only the Code-node JS was exercised, in plain node.
2. Telegram delivery, and the failed-send retry path (Mark Seen runs only after Telegram succeeds).
3. The cron run environment (PATH, python 3.12, macOS Full Disk Access). The sample crontab line was never installed.
4. Review fixes flagged "requires human verification" (logic fixes, covered by tests only):
   - P1: CR-02 (H1 args), CR-03 (regex widening).
   - P2: CR-01 and WR-06 (cap removal), WR-02 (YAML run forms), WR-04 (H5 pin forms and discovery).
   - P3: CR-01 (exit-code handling), WR-01 (empty path), WR-05 (root dedupe).
   - P4: CR-01 (Mark Seen), WR-01 (dedupe pruning), WR-03 (URL validation), WR-04 (inode-based --exclude).

**Unfixed review Info items (all skipped by design):**
- P1 IN-01: duplicate Findings for identical hook commands. IN-02: other command-bearing keys (`statusLine`, `apiKeyHelper`, MCP `command`) are not checked. IN-03: prefix allowlist can be bypassed (`git -c`, `eslint --plugin`).
- P2 IN-01: `_symlink_findings` is over-broad. IN-02: `target_for` can return a `None` check callable (latent). IN-03: unsorted imports, and `iocs.json` holds placeholder entries only, so H5 is inert on real data until populated.
- P3 IN-01: a 70 exit prints only the exception type, with no debug opt-in. IN-02: fd leak and unguarded `dup2` in the BrokenPipe handler. IN-03: e2e tests use `cwd=REPO_ROOT` and `-m dev_guard`, with no installed-entry-point test. This audit's smoke test did that run manually, but no automated test does.
- P4 IN-01: Telegram `appendAttribution: false` is not set (0 matches in the workflow JSON). The message cap was done, the attribution flag was not. IN-02: the node dedupe tests and the wrapper tests skip silently when node, bash or curl is missing.

**Known limits and shortcuts:**
- `WR-05` (P1, find_line): an earlier unrelated line with the same text can win the reported line number.
- The allowlist is prefix-match. The workflow scan is line-based, with no YAML parser.
- The wrapper permanently excludes the repo's `tests/` dir. A failed cron run leaves only a log line (`~/.dev-guard-cron.log`) and no alert.
- n8n static-data dedupe keeps a fingerprint only while the finding persists. It is pruned when absent, so a finding that goes away and returns alerts again.
- `--exclude` matches directory subtrees only. A single file is not excluded (the README and `--help` say so correctly).
- Performance: real `~/Projects` scan took 15.1s at Phase 3 against a 30s budget. It was not re-timed in this audit.
- The wrapper with no args scans the real `~/Projects` and `~/.claude` (not run here).
- v2 scope: Linux and Windows paths, a live IOC feed, obfuscation-resistant detection.
